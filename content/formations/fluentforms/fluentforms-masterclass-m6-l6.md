# Script video — Module 6, Lecon 6 : Partial entries

**Formation** : FluentForms Masterclass Formulaires

**Module** : 6 — Quiz, surveys et analytics
**Lecon** : 6/6 — Partial entries
**Duree** : 6 min (~900 mots)
**Type** : Video HeyGen + voix ElevenLabs
**Ecran** : Face camera intro/outro, screencast partial entries settings, slide strategie relance
**Objectif** : Capturer les soumissions partielles, analyser les abandons et relancer via FluentCRM

---

**[INTRO — face camera]**

Un visiteur commence a remplir ton formulaire. Il entre son prenom, son email, commence a selectionner ses options — et il part. Il ferme l'onglet, il est distrait, il hesite.

Sans partial entries, cette personne est perdue. Avec partial entries, tu recuperes ce qu'elle a deja saisi. C'est l'equivalent du panier abandonne pour les formulaires.

**[SECTION 1 — screencast "Activer les partial entries"]**

FluentForms Pro. Direction Form Settings, dans ton formulaire. Cherche l'option "Enable Partial Entries" ou "Save Partial Entries".

Active-la. A partir de maintenant, chaque fois qu'un visiteur commence a remplir le formulaire, les champs saisis sont sauvegardes — meme si le formulaire n'est pas soumis.

Par defaut, FluentForms sauvegarde apres chaque changement de champ (quand le curseur quitte un champ). Pas besoin que le visiteur clique sur un bouton.

**[SECTION 2 — screencast "Consulter les partial entries"]**

Va dans FluentForms, Entries pour ton formulaire. Tu vois deux types d'entrees : les soumissions completes (statut "Completed") et les partielles (statut "Partial" ou "Abandoned").

Clique sur une entree partielle. Tu vois quels champs ont ete remplis et a quel moment le visiteur a abandonne.

Si le visiteur a rempli son prenom et son email mais n'a pas rempli les champs suivants, tu sais que l'abandon est arrive a l'etape 2. Si 80% de tes partial entries abandonnent au meme endroit, c'est cet endroit qui pose probleme.

**[SECTION 3 — slide "Analyser les points d'abandon"]**

L'analyse des partial entries te dit ou et pourquoi les gens quittent.

Les causes les plus frequentes :

Le formulaire est trop long. Si les abandons commencent a partir du 5eme champ, c'est que tu demandes trop d'informations. Solution : reduire les champs ou passer en multi-etapes pour reduire la perception de longueur.

Un champ est confus. Si tout le monde abandonne au meme champ, c'est que le label n'est pas clair, les options ne correspondent pas, ou le champ est trop intrusif (demander le numero de telephone trop tot par exemple).

Le prix fait fuir. Pour les formulaires de paiement, si l'abandon arrive apres l'affichage du prix, c'est le prix ou la perception de valeur qui bloque. Pas le formulaire.

Le champ carte bancaire. Beaucoup de gens abandonent juste avant d'entrer leur carte. C'est normal — c'est un point de friction naturel. Mais si le taux est tres eleve, ajoute des elements de confiance : badges de securite, garantie, temoignages.

**[SECTION 4 — screencast "Relancer les abandons"]**

Si les partial entries contiennent un email, tu peux relancer ces contacts.

Exporte les partial entries en CSV. Filtre pour ne garder que celles avec un email valide. Importe ces emails dans FluentCRM avec le tag "form-abandoned".

Cree une automation dans FluentCRM : trigger "Tag Applied" = "form-abandoned".

Email de relance. Objet : "Tu as oublie quelque chose ?". Corps : rappel de ce que le visiteur etait en train de faire + lien direct vers le formulaire. Si c'est un formulaire de paiement, ajoute un coupon : "Voici un code de 10% pour finaliser ta commande : COMEBACK10".

Timing : envoie la relance 1h apres l'abandon. Pas immediatement — ca fait surveillance. Pas le lendemain — le visiteur a deja oublie. 1h est le sweet spot.

Un deuxieme email a J+3 si pas de reponse : "Derniere chance — ton code COMEBACK10 expire demain."

Le taux de recuperation des partial entries varie entre 5 et 15%. Sur un formulaire de paiement a 200 euros, 10 abandons recuperes a 10% ca fait 200 euros de chiffre d'affaires sauve.

**[SECTION 5 — screencast "Optimiser en continu"]**

Les partial entries ne sont pas un outil ponctuel. C'est un outil d'amelioration continue.

Chaque mois, regarde tes partial entries. Identifie le formulaire avec le plus d'abandons. Identifie l'etape ou les gens quittent. Teste une amelioration (moins de champs, meilleur wording, meilleur placement).

Mesure le mois suivant. Le taux d'abandon a baisse ? L'amelioration fonctionne. Il n'a pas bouge ? Teste autre chose.

C'est un cycle : mesurer → identifier → ameliorer → mesurer. Les formulaires qui convertissent le mieux sont ceux qui ont ete optimises a partir des donnees d'abandon.
