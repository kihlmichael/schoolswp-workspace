**[INTRO - face caméra]**

Tu as ton compte OttoKit. Maintenant, il faut installer le plugin sur ton site WordPress. C'est le pont entre ton site et la plateforme cloud. Sans lui, OttoKit ne peut pas voir tes plugins ni réagir aux événements de ton site.

[Tape "OttoKit" dans le champ de recherche]
[Montre le résultat : "OttoKit: All-in-One Automation Platform" par Brainstorm Force]

Tu vas voir le plugin apparaître. Vérifie bien : c'est par Brainstorm Force, l'équipe derrière Astra et Spectra. Le slug technique reste "suretriggers" - c'est l'ancien nom, mais c'est bien le bon plugin.

[Clique sur "Installer maintenant"]
[Attends l'installation]
[Clique sur "Activer"]

Le plugin est activé. Tu vas être redirigé automatiquement vers la page de configuration OttoKit.

**[ÉCRAN - screencast page de réglages OttoKit dans WordPress]**

[Montre la page de réglages avec le bouton "Connect"]

Voilà la page de connexion. C'est ici qu'on va relier ton site à ton compte cloud. Mais ça, c'est la prochaine leçon.

Avant de continuer, vérifie deux choses :

[Montre le menu latéral WordPress]

[Clique sur Extensions > Extensions installées]

## Leçon 2.3 - Connecte ton site WordPress à la plateforme

**Durée** : 6 min
**Type** : Vidéo HeyGen
**Écran** : Face caméra pour intro/conclusion, screencast WordPress admin + app.ottokit.com

---

**[INTRO - face caméra]**

Le plugin est installé. Maintenant, on va connecter ton site WordPress à la plateforme cloud OttoKit. C'est cette connexion qui permet à OttoKit de détecter tes plugins, tes formulaires, tes produits WooCommerce - tout ce qui existe sur ton site.

**[ÉCRAN - screencast page de réglages OttoKit dans WordPress]**

[Montre la page de réglages OttoKit]
[Pointe le bouton "Connect" ou "Connect with OttoKit"]

Clique sur ce bouton.

[Clique sur "Connect"]

Une fenêtre s'ouvre pour te connecter à ton compte OttoKit. Si tu es déjà connecté dans ton navigateur, ça se fait automatiquement. Sinon, entre tes identifiants.

[Montre le flux d'authentification]
[Montre l'écran d'autorisation : "Allow this site to connect?"]
[Clique sur "Allow" ou "Authorize"]

La connexion s'établit. OttoKit va maintenant scanner ton site WordPress pour détecter les plugins compatibles.

**[ÉCRAN - screencast app.ottokit.com > Connections]**

[Ouvre app.ottokit.com dans un nouvel onglet]
[Clique sur "Connections" dans la barre latérale]
[Montre la connexion WordPress qui vient d'apparaître]

Voilà ton site WordPress connecté. Tu vois le nom de ton site, l'URL, et la liste des plugins détectés.

[Pointe la liste des plugins détectés]

OttoKit a trouvé automatiquement les plugins compatibles installés sur ton site. Par exemple :

- WooCommerce (si installé)
- FluentCRM (si installé)
- Gravity Forms ou Fluent Forms (si installé)
- TutorLMS (si installé)

C'est grâce à cette détection que tu pourras utiliser des triggers et des actions spécifiques à chaque plugin.

**[ÉCRAN - screencast vérification de la connexion]**

Pour vérifier que tout fonctionne, fais un test simple :

[Retourne dans WordPress admin]
[Montre la page OttoKit dans WordPress : statut "Connected"]
[Montre le badge vert ou l'indicateur de connexion active]

Le statut affiche "Connected". C'est bon.

Si tu vois "Disconnected" ou un message d'erreur, pas de panique. On traitera les problèmes courants dans la leçon 2.7.

**[ÉCRAN - slide "Prérequis techniques"]**

Un rappel important : la connexion nécessite :

- **HTTPS** : ton site doit avoir un certificat SSL actif
- **WordPress 6.0+** : les versions antérieures ne sont pas supportées
- **PHP 7.4+** : vérifie dans Outils > Santé du site
- **WP-Cron actif** : nécessaire pour la communication en temps réel

Si un de ces prérequis manque, la connexion échouera ou sera instable.

**[TRANSITION - face caméra]**

Ton site et ton compte OttoKit communiquent. Prochaine étape : connecter ta première app externe. On va commencer par Google Sheets.

**Points clés**

- Prérequis : HTTPS, WordPress 6.0+, PHP 7.4+, WP-Cron actif
- Vérifie le statut "Connected" dans WordPress après la connexion

## Leçon 2.5 - Crée ton premier workflow : formulaire → Google Sheets

**Durée** : 8 min
**Type** : Vidéo HeyGen (démo)
**Écran** : Face caméra pour intro/conclusion, screencast app.ottokit.com workflow builder

---

**[INTRO - face caméra]**

C'est le moment. Tu vas créer ton premier workflow de A à Z. L'objectif : chaque fois qu'un visiteur remplit un formulaire sur ton site, ses informations sont automatiquement ajoutées dans un Google Sheets. Zéro copier-coller, zéro oubli.

**[ÉCRAN - screencast app.ottokit.com]**

[Clique sur "Workflows" dans la barre latérale]
[Clique sur "Create Workflow" ou le bouton "+"]

OttoKit te propose deux options : partir de zéro ou utiliser un template. On va partir de zéro pour bien comprendre chaque étape.

[Sélectionne "Start from scratch" / "Blank workflow"]

Première chose : donne un nom clair à ton workflow.

[Clique sur le titre du workflow]
[Tape : "Formulaire contact → Google Sheets"]

Un bon nom décrit ce que fait le workflow. Tu vas en créer des dizaines - si tu les appelles "Workflow 1", "Test", "Sans titre", tu seras perdu dans une semaine.

**[ÉCRAN - screencast workflow builder : ajout du trigger]**

Tu es dans le canvas builder. C'est l'éditeur visuel d'OttoKit.

[Montre le canvas vide avec le bouton "Add Trigger"]
[Clique sur "Add Trigger"]

On va configurer le trigger - l'événement déclencheur. Cherche le plugin de formulaire que tu utilises.

[Tape "Fluent Forms" dans la recherche (ou Gravity Forms, WPForms selon le site)]
[Sélectionne le plugin]
[Montre la liste des triggers disponibles pour ce plugin]
[Sélectionne "Form Submitted" ou "New Form Submission"]

Maintenant, OttoKit te demande de préciser quel formulaire.

[Montre le menu déroulant avec la liste des formulaires du site]
[Sélectionne le formulaire de contact]

Pour que OttoKit sache quels champs sont disponibles, clique sur "Fetch Data".

[Clique sur "Fetch Data"]
[Montre les champs qui apparaissent : nom, email, message, etc.]

OttoKit a récupéré la structure de ton formulaire. Tu vois les champs : nom, email, message. Ce sont ces données qu'on va envoyer dans Google Sheets.

[Clique sur "Save" pour valider le trigger]

**[ÉCRAN - screencast workflow builder : ajout de l'action]**

Le trigger est en place. Maintenant, on ajoute l'action : envoyer les données dans Google Sheets.

[Clique sur le "+" sous le trigger]
[Clique sur "Add Action"]
[Tape "Google Sheets" dans la recherche]
[Sélectionne Google Sheets]
[Montre la liste des actions disponibles]
[Sélectionne "Add Row" ou "Insert Row"]

OttoKit te demande de configurer l'action. Plusieurs champs à remplir :

[Montre le champ "Connection"]
[Sélectionne la connexion Google Sheets créée à la leçon 2.4]

[Montre le champ "Spreadsheet"]
[Sélectionne le tableur cible dans la liste]

Si tu n'as pas encore créé le tableur, ouvre Google Sheets dans un autre onglet et crée un nouveau document avec les colonnes : Nom, Email, Message, Date.

[Montre le champ "Sheet" (onglet)]
[Sélectionne "Sheet1" ou l'onglet voulu]

Maintenant, le mapping des données. C'est la partie où tu dis à OttoKit : "mets le nom dans la colonne Nom, l'email dans la colonne Email".

[Montre les champs de mapping]
[Clique sur le champ "Nom" côté Sheets]
[Montre le sélecteur de données dynamiques]
[Sélectionne le champ "name" du trigger]

[Répète pour Email : sélectionne "email" du trigger]
[Répète pour Message : sélectionne "message" du trigger]

Chaque colonne de ton tableur est associée à un champ du formulaire. C'est ce qu'on appelle le data mapping.

[Clique sur "Save" pour valider l'action]

**[ÉCRAN - screencast vue d'ensemble du workflow]**

[Montre le workflow complet dans le canvas : trigger en haut, action en dessous, flèche entre les deux]

Voilà ton premier workflow. Il fait exactement ce qu'on voulait :

1. Un visiteur remplit le formulaire de contact
2. OttoKit récupère les données
3. OttoKit ajoute une ligne dans ton Google Sheets

Deux blocs. Une connexion. C'est tout.

**[TRANSITION - face caméra]**

Ton workflow est configuré, mais il n'est pas encore actif. Dans la prochaine leçon, on va le tester avec de vraies données et le publier.

---

**Points clés**
- Toujours nommer clairement tes workflows (action + destination)
- Un workflow = 1 trigger + 1 ou plusieurs actions
- "Fetch Data" récupère la structure des champs disponibles
- Le data mapping relie les champs du trigger aux colonnes de l'action
- Un workflow simple = 2 blocs connectés

## Leçon 2.7 - Troubleshooting : les 5 erreurs les plus courantes à l'installation

**Durée** : 5 min
**Type** : Vidéo HeyGen
**Écran** : Face caméra pour intro/conclusion, screencast WordPress admin + app.ottokit.com

---

**[INTRO - face caméra]**

L'installation s'est bien passée pour toi ? Tant mieux. Mais si tu es bloqué, ou si un élève te pose la question, voici les 5 problèmes les plus fréquents et leurs solutions.

**[ÉCRAN - slide "Erreur 1 : Connexion échouée - SSL manquant"]**

**Problème** : tu cliques sur "Connect" mais rien ne se passe, ou tu obtiens une erreur "SSL required".

**Cause** : ton site n'est pas en HTTPS. OttoKit refuse les connexions non sécurisées.

**Solution** :

[Montre la barre d'adresse du navigateur - HTTP vs HTTPS]

- Vérifie que ton hébergeur a activé le certificat SSL
- Force HTTPS dans les réglages WordPress : Réglages > Général > remplace http:// par https://
- Si tu utilises Cloudflare, active "Always Use HTTPS"

**[ÉCRAN - slide "Erreur 2 : Le plugin ne détecte pas les plugins WP"]**

**Problème** : tu connectes ton site, mais OttoKit ne voit aucun plugin compatible.

**Cause** : les plugins ne sont pas actifs, ou le cache empêche la détection.

**Solution** :

[Montre la page Extensions dans WordPress]

- Vérifie que les plugins (WooCommerce, FluentCRM, etc.) sont bien actifs
- Vide le cache de ton site (plugin de cache, serveur)
- Déconnecte et reconnecte ton site dans OttoKit
- Attends 2-3 minutes : la détection n'est pas toujours instantanée

**[ÉCRAN - slide "Erreur 3 : Timeout à la connexion"]**

**Problème** : la connexion démarre mais tourne en boucle, puis échoue avec un timeout.

**Cause** : ton serveur met trop de temps à répondre - souvent un hébergement mutualisé trop lent.

**Solution** :

- Désactive temporairement les plugins de cache et de sécurité
- Augmente le timeout PHP dans wp-config.php (si tu as accès) :

```
set_time_limit(300);
```

- Contacte ton hébergeur pour vérifier que les requêtes REST API ne sont pas bloquées

**[ÉCRAN - slide "Erreur 4 : Pare-feu ou plugin de sécurité qui bloque"]**

**Problème** : la connexion échoue avec une erreur 403 ou "Forbidden".

**Cause** : un plugin de sécurité (Wordfence, Sucuri, iThemes Security) bloque les requêtes d'OttoKit.

**Solution** :

[Montre les réglages Wordfence en exemple]

- Ajoute les IPs d'OttoKit en liste blanche dans ton plugin de sécurité
- Désactive temporairement le firewall applicatif pour tester
- Vérifie les règles du pare-feu de ton hébergeur (ModSecurity, etc.)
- Si ça fonctionne avec le firewall désactivé, réactive-le et ajoute les exceptions

**[ÉCRAN - slide "Erreur 5 : WP-Cron désactivé ou défaillant"]**

**Problème** : la connexion fonctionne, mais les triggers ne se déclenchent pas ou avec un gros retard.

**Cause** : WP-Cron est désactivé ou ne fonctionne pas correctement. OttoKit utilise le cron pour communiquer avec le cloud.

**Solution** :

[Montre le fichier wp-config.php]

- Vérifie que cette ligne n'est PAS dans ton wp-config.php :

```
define('DISABLE_WP_CRON', true);
```

- Si WP-Cron est désactivé volontairement (cron système), assure-toi que le cron système tourne bien toutes les minutes
- Installe le plugin "WP Crontrol" pour vérifier que les tâches cron sont planifiées

[Montre Outils > Santé du site dans WordPress]

- Va dans Outils > Santé du site > Info. Vérifie que le cron est marqué comme actif.

**[ÉCRAN - slide "Résumé des 5 erreurs"]**

| Erreur | Cause | Solution rapide |
|--------|-------|-----------------|
| Connexion échouée | SSL manquant | Activer HTTPS |
| Plugins non détectés | Plugins inactifs ou cache | Réactiver + vider le cache |
| Timeout | Serveur lent | Désactiver cache/sécurité temporairement |
| Erreur 403 | Pare-feu bloque | Ajouter IPs en whitelist |
| Triggers en retard | WP-Cron désactivé | Vérifier wp-config.php |

**[TRANSITION - face caméra]**

Si tu rencontres un problème qui n'est pas dans cette liste, la première chose à faire : va dans l'historique OttoKit et lis le message d'erreur. Il est souvent explicite. Sinon, le support Brainstorm Force est réactif.

Tu as terminé le Module 2. Tu sais installer OttoKit, connecter ton site, ajouter une app, créer un workflow, le tester et le publier. Place au quiz pour valider tout ça.

- HTTPS est obligatoire pour connecter OttoKit
- Les plugins WordPress doivent être actifs pour être détectés
- Les plugins de sécurité et le cache sont les premières causes de blocage
- WP-Cron doit être actif pour que les triggers fonctionnent
- L'historique OttoKit affiche les messages d'erreur détaillés
