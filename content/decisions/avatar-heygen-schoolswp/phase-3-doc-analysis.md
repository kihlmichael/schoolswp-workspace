## Resolution des claims de la Phase 2

1. **Realisme d Avatar V et stabilite d identite sur les longs formats** : **Partiel**. La doc confirme qu Avatar V offre "more natural motion and lip-sync through cross-reference-driven animation" et coche "Better motion & lip-sync quality" (developers.heygen.com/models.md). En revanche le superlatif exact "le plus realiste / most realistic" n apparait PAS verbatim (le mot employe est "latest engine" et "more natural"). La stabilite d identite sur les longs formats n est documentee nulle part dans les sources consultees. Source : developers.heygen.com/models.md.

2. **Qualite reelle a partir d une seule photo (Photo Avatar / Avatar IV)** : **Confirme** sur le principe (une seule photo suffit), **Partiel** sur la qualite chiffree. "Simply upload a photo, and we'll transform it into a dynamic, animated version that lip-syncs perfectly to your script" et "no video recording needed" (help.heygen.com/en/articles/10034438 ; developers.heygen.com/docs/create-avatar). La doc donne des criteres de cadrage (visage proche des proportions humaines, yeux/bouche visibles) mais aucune metrique de qualite ni resolution/format minimum de la photo source. Source : help.heygen.com/en/articles/10034438.

3. **Duree d enregistrement requise pour le Digital Twin** : **Confirme, mais le claim "15 secondes a 2 minutes" est infirme en borne basse**. La doc Digital Twin indique "Record at least 2 minutes... up to 5 minutes for the best training results" et "Record at least one 2-minute long uninterrupted speech", avec une version rapide minimale de "30-second quick recording". Le chiffre "15 secondes" provient des pages Avatar V (heygen.com/avatars/avatar-v et une note community), PAS de la doc Digital Twin. Donc pour le Digital Twin documente : 30 secondes minimum (version rapide) a 5 minutes, standard recommande 2 minutes. Source : help.heygen.com/en/articles/12089286 et .../8389138.

4. **Qualite du clonage de voix et du lip-sync en francais** : **Non documente**. Le clonage existe ("POST /v3/voices/clone") et le lipsync audio est confirme (developers.heygen.com/reference/create-video), mais le support du francais (voix FR, locale fr-FR) n est PAS liste explicitement (exemples cites : English, Spanish, Japanese ; en, pt, zh). Aucune metrique de qualite du clonage ni du lip-sync FR. Source : developers.heygen.com/docs/voices/overview.

5. **Disponibilite des fonctionnalites par plan** : **Partiel**. Confirme : slots Photo Avatar (Free 3, plans payants illimite), SCORM (Business/Enterprise uniquement), proprietes des outputs (Free = non commercial). Non documente : disponibilite par plan du Brand System, du Brand Glossary, de l interactivite (avatars interactifs), et le detail des slots d avatars video par plan. Sources : help.heygen.com/en/articles/10034438 ; .../10549082 ; heygen.com/terms.

6. **Cout en credits par minute et par generation** : **Confirme cote plan web, Non documente cote API**. Plan web : Avatar III 3 credits/min, Avatar IV/V 20 credits/min, Video Agent 20 credits/min, traduction 2 ou 5 credits/min (heygen.com/pricing). Cote API Pay-As-You-Go : seul le minimum de 5 $ pour demarrer est indique, AUCUN taux $/min par moteur. Source : heygen.com/pricing et heygen.com/api-pricing.

7. **Credits API = enveloppe distincte des credits du plan** : **Confirme**. "MCP usage is deducted from your web plan's premium credit balance, while Skills and Direct API usage is deducted from your API dashboard balance. The two billing pools are independent." Nuance importante : le MCP, lui, consomme les credits du PLAN web, pas le wallet API. Source : heygen.com/api-pricing.

8. **Export SCORM et integration LMS (TutorLMS)** : **Partiel**. SCORM confirme (SCORM 1.2 et 2004, export ZIP, seuil de completion, Auto-update), reserve aux plans Business et Enterprise. La compatibilite est annoncee pour "any SCORM-compliant LMS" mais TutorLMS n est PAS nomme explicitement. Source : help.heygen.com/en/articles/10549082.

9. **Extraction automatique de la charte via Brand System par URL** : **Confirme**. "You can upload your website URL, and HeyGen will automatically generate a brand system based on your site" (logos, polices, couleurs, hex). Disponibilite par plan non documentee. Source : heygen.com/academy/brand-kit/how-to-create-your-brand-kit.

10. **Coherence du visage entre de nombreux looks** : **Partiel**. La doc confirme la mecanique : un avatar group est une identite de personnage, "Each group can have multiple looks" et "one of the group's looks is used as the base that conditions the generation" (developers.heygen.com/docs/create-avatar) ; cote Photo Avatar, generation de nouveaux looks via upload de photos de reference (help.heygen.com/en/articles/10034438). Mais aucune garantie ni metrique documentee sur la fidelite/coherence du visage entre les looks. Source : developers.heygen.com/docs/create-avatar.

11. **Maturite du pipeline d automatisation (Video Agent API, MCP, Hyperframes)** : **Confirme pour Video Agent API et MCP, Non documente pour Hyperframes**. Video Agent ("A single POST /v3/video-agents produces a finished video"), MCP HeyGen ("Use these tools directly. No API key... videos consume the user's existing HeyGen plan credits"), webhooks (CRUD, HMAC, retries 24h, callback_url) et ladder MCP > CLI > API sont tous documentes (developers.heygen.com/docs/for-ai-agents et /docs/webhooks). "Hyperframes" n apparait dans AUCUNE source HeyGen consultee : c est un outil interne schoolsWP, sans rapport documente avec HeyGen. Sources : developers.heygen.com/docs/for-ai-agents ; developers.heygen.com/docs/webhooks.

## Ce que ca implique pour l avatar de Michael (faits -> implications)

**Faits etablis (doc) et leurs implications directes :**

- Fait : une seule photo suffit pour creer un Photo Avatar, sans tournage video, et le Photo Avatar ne requiert PAS de video de consentement cote API (digital_twin uniquement). Implication : le chemin le plus rapide pour Michael est le Photo Avatar a partir d une de ses photos, en cadrant le visage large, bien eclaire, proportions humaines. Pas d etape de consentement video a gerer dans ce mode.

- Fait : si Michael veut un Digital Twin video, il doit filmer une prise continue de 2 a 5 minutes en 1080p minimum, avec son, puis enregistrer une video de consentement. Implication : le Digital Twin demande un setup de tournage et une etape legale ; c est un investissement plus lourd que le Photo Avatar, justifie seulement si la fidelite attendue le merite.

- Fait : Avatar IV est le moteur par defaut et supporte motion_prompt + expressiveness sur les photo avatars ; Avatar V demande un opt-in explicite et une verification d eligibilite par look (400 sinon). Implication : Michael peut demarrer sur Avatar IV sans configuration, et ne tester Avatar V que sur les looks eligibles, en acceptant de perdre motion_prompt/expressiveness.

- Fait : le lipsync accepte un audio_url public, mutuellement exclusif avec le script TTS. Implication : schoolsWP peut brancher une voix ElevenLabs (deja dans la stack) via une URL audio publique, plutot que de dependre du TTS interne ; cela contourne aussi l incertitude sur le support FR du TTS HeyGen.

- Fait : les credits du MCP sortent du PLAN web, les credits de la cle API sortent d un wallet separe, et Avatar IV/V coute 20 credits/min cote plan.
