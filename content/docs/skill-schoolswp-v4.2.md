## Règles SEO

Pour les articles :

- H1 unique
- Title orienté résultat
- Meta description de 145 à 155 caractères
- Slug en kebab-case
- URL evergreen

Slugs : 2 règles dures

1. **Aucune date** dans le slug, sauf demande explicite.
2. **Aucune mention "schoolswp"** dans le slug. Le domaine porte déjà le nom, le répéter dans l'URL crée un doublon parasite.

OK dans le contenu visible (title, meta, alt, XP*), interdit dans le slug.

Reste :

- intention de recherche claire
- réponse rapide en début d'article
- maillage interne utile
- FAQ si pertinente

Ne pas écrire pour Google au détriment du lecteur.

Écrire d'abord pour aider.

Optimiser ensuite pour être trouvé.

## Recherche concurrentielle obligatoire (étape 0)

> Source : BRAND_RULES.md règle 32.

Tout article visant un mot-clé SEO passe par une analyse des 3 à 5 articles top-ranked avant rédaction (10-15 min).

Optionnel pour newsletter, post social, script vidéo.

Process :

- identifier les 3 à 5 URLs top-ranked sur le mot-clé cible
- lister les angles dominants (méthode, comparatif, tutoriel, débat)
- repérer les questions traitées dans les H2 / H3
- identifier les manques : ce que personne ne dit, ce qui est mal expliqué, ce qui est obsolète
- choisir l'angle schoolsWP : combler un manque bat répéter l'existant

Livrables intermédiaires (à archiver dans `content/decisions/<slug>.md` ou en tête du brief) :

- mot-clé cible + intention (info / nav / transac)
- 3 à 5 URLs analysées
- angle retenu en 1 phrase
- liste des 3 manques exploités

**Règle dure** : si l'article n'apporte rien de plus que le top 3 actuel, on ne le publie pas. On le retravaille ou on l'abandonne.

## Comparatifs et avis : respect du concurrent

> Source : BRAND_RULES.md règle 31 + mémoire `feedback_competitor_reviews_respect.md`.

Un avis ou comparatif schoolsWP ne dénature jamais l'outil tiers évalué. **Cinq garde-fous appliqués systématiquement** :

1. **Limites factuelles, pas charge** : décrire les manques observés sur des cas d'usage précis. Pas de listage à charge ("frustrations bloquantes", "défauts critiques", "X est dépassé"). Préférer "limites observées sur mes cas d'usage".
2. **Pas d'affirmation universelle** : interdire "X est meilleur que Y", "X gagne dans 90 % des cas". Ancrer : "dans mon cas", "sur mes besoins schoolsWP", "pour les usages que j'ai testés", "je préfère X pour...".
3. **Section "Pour qui [concurrent] reste pertinent" obligatoire** : tout avis qui pivote vers un autre outil inclut une section explicite décrivant les profils pour lesquels l'outil évalué reste un bon choix. Pas de bascule unilatérale.
4. **Pas de notes chiffrées globales arbitraires** : interdire "7/10 vs 9/10" sans grille. Si note, grille de critères explicite, chaque score argumenté, critère rattaché à un cas d'usage testé.
5. **Verdict personnel, pas universel** : title, intro et conclusion doivent signaler que c'est un choix de Michaël pour schoolsWP, pas un classement objectif sur le marché.

Anti-patterns à bannir : "Pourquoi Y reste meilleur", "Mes frustrations bloquantes", "X est dépassé", "X gagne dans 90 % des cas", "verdict pro-Y".

Patterns à reproduire : "Pourquoi je suis passé à Y", "Les limites observées sur mes cas d'usage", "Pour qui X reste pertinent", "Je préfère Y pour mes besoins schoolsWP", "Sur mes 12 critères, voici le verdict".

Cette règle prime sur l'objectif affiliate. Le respect du concurrent ne se négocie pas contre le revenu.
