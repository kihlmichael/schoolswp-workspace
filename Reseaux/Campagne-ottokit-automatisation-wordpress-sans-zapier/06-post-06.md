## B. Contenu du post

### Slide 1 (hook)
La stack d'automatisation qui fait tourner schoolswp.com en 2026.
Sans Zapier. Sans Make. Sans abonnement externe.

### Slide 2 — Les 3 piliers
OttoKit + FluentCRM + Fluent Forms.
Ces 3 plugins forment une boucle d'automatisation complète sur WordPress.
Chacun a un rôle précis.

### Slide 3 — Fluent Forms (déclencheur)
Tout commence par un formulaire.
Fluent Forms capture : inscriptions, demandes de contact, achats, leads.
Il transmet les données aux deux autres plugins via OttoKit.

### Slide 4 — OttoKit (orchestrateur)
OttoKit reçoit les événements et déclenche les actions.
Exemple : formulaire soumis → créer contact FluentCRM → ajouter tag → déclencher séquence.
C'est le chef d'orchestre de la stack.

### Slide 5 — FluentCRM (exécuteur)
FluentCRM reçoit les contacts qualifiés.
Il envoie les emails, gère les séquences, suit les comportements.
Sans quitter WordPress.

### Slide 6 — 3 workflows actifs sur schoolswp.com
Workflow 1 : Lead magnet
Formulaire → OttoKit → contact FluentCRM → tag "lead-magnet" → séquence 5 emails

Workflow 2 : Achat formation
WooCommerce → OttoKit → accès TutorLMS → email de bienvenue → tag "client-actif"

Workflow 3 : Contenu protégé
Fluent Forms inscription → OttoKit → tag membre → accès contenu FluentCRM

### Slide 7 — Ce que Zapier faisait avant
Avant OttoKit, ces 3 workflows passaient par Zapier.
29 €/mois pour faire des appels API entre des plugins WordPress.
Désormais, tout reste dans WordPress.

### Slide 8 — Limites de la stack
OttoKit ne remplace pas Zapier pour tout.
Si tu connectes WordPress vers Notion, Slack ou Airtable → Zapier reste utile.
Si ton écosystème est WordPress-centré → la stack ci-dessus suffit.

### Slide 9 (CTA)
La stack complète : Fluent Forms + OttoKit + FluentCRM.
Installation → configuration → workflows : le guide est en bio.
Lien direct vers le tuto schoolsWP.
