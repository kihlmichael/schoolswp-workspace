# Authority System 90™ — by schoolsWP

Programme d'accompagnement 90 jours. Objectif : amener un porteur de projet de **"je publie au feeling"** à **"j'ai un système d'autorité qui génère trafic + leads"**.

Le socle stratégique est celui de schoolsWP (Architecture → Autorité → Performance), mais **tout le contenu s'adapte à la niche du client** : noms, exemples, livrables, vocabulaire métier.

---

## Inputs

Avant de générer quoi que ce soit, recueille ces informations (pose les questions manquantes ou formule des hypothèses intelligentes en mode Direct) :

| Input | Description | Requis |
|---|---|---|
| `porteur` | Nom ou marque du porteur de projet | Oui |
| `niche` | Métier ou secteur ciblé (ex: garagiste, consultant WordPress, coiffeur) | Oui |
| `offre` | Type d'accompagnement ou d'offre proposée | Oui |
| `maturite` | Niveau du projet (débutant / intermédiaire / avancé) | Recommandé |
| `objectif` | Objectif principal du client (trafic, leads, notoriété, CA…) | Recommandé |
| `mode` | `conception` / `vente` / `execution` / `direct` | Oui |
| `semaine` | Semaine en cours (1–12) — uniquement en mode `execution` | Si execution |

---

## Outputs obligatoires

Quelle que soit la demande, le livrable doit toujours inclure :

1. **Contenu structuré en Markdown** — prêt à copier/coller ou envoyer au client
2. **Adaptation à la niche** — vocabulaire métier, exemples concrets, livrables contextualisés
3. **Plan d'action concret** — étapes claires, pas de vague
4. **Prochaines étapes explicites** — ce que le client doit faire ensuite

Selon le mode :

| Mode | Output principal |
|---|---|
| `conception` | Structure de programme / offre / accompagnement |
| `vente` | Argumentaire, pitch, copy ou présentation prête à utiliser |
| `execution` | Plan de session ou plan d'action de la semaine en cours |
| `direct` | Réponse opérationnelle immédiate adaptée au besoin |

**Exemple 1 — mode execution**

Entrée : "Créer le plan de session semaine 3 pour un consultant WordPress qui aide les restaurateurs"

Sortie :
```
## Session semaine 3 — [Porteur] / Restauration WordPress

**Objectif de la semaine :** Valider l'architecture de clusters sémantiques

**Déroulé (90 min) :**

2. Revue de la carte de clusters — ajustements (30 min)
3. Plan de la page pilier — structure + angle (30 min)
4. Prochaines actions — assignation (15 min)

- Carte de clusters validée (Notion / Sheets)
- Titre + plan détaillé de la page pilier

**Actions avant semaine 4 :**
- Rédiger l'intro + structure H2 de la page pilier
- Identifier 3 concurrents sur la requête pilier
```

## Structure du programme (3 blocs)

Le cadre stratégique est fixe. Le contenu s'adapte à chaque niche.

### BLOC 1 — STRUCTURE (Jours 1–30)

**Transformation :** du flou à l'architecture

Ce qu'on construit :
- Positionnement clair sur la niche
- Angle différenciant
- Carte de clusters sémantiques (ou thématiques selon la niche)
- Page / contenu pilier stratégique
- Tunnel logique (découverte → confiance → conversion)

**Frameworks :** Architecture Blueprint · Decision Engine

**Livrable client :** Plan d'écosystème complet validé

---

### BLOC 2 — AUTORITÉ (Jours 31–60)

**Transformation :** du plan au contenu d'autorité

Ce qu'on construit :
- 1 contenu pilier massif (optimisé IA / SEO selon la niche)
- 3 à 5 contenus satellites positionnés
- FAQ optimisées pour la citabilité (Google, IA, recommandations)
- Structure avancée (schema, maillage, balises)

**Frameworks :** Strategic Engine · Omnichannel Engine

**Livrable client :** Cluster d'autorité publié, prêt à ranker et être cité

---

### BLOC 3 — PERFORMANCE (Jours 61–90)

**Transformation :** du contenu publié au système qui s'améliore

Ce qu'on construit :
- Système de test (titres, CTAs, messages clés)
- Optimisation des pages prioritaires
- Amélioration de la conversion
- Système d'itération continue (analytics + plan mensuel)

**Frameworks :** Growth Loop · Performance Loop

**Livrable client :** Dashboard de pilotage + plan d'optimisation continue

## Format du programme

- 1 session stratégique par semaine (90 min)
- 1 audit intermédiaire fin Bloc 1 et fin Bloc 2
- 1 plan personnalisé actualisé à chaque bloc
- Templates et frameworks fournis à chaque étape
- Support asynchrone structuré entre les sessions

## Actions suivantes (toujours inclure)

Après chaque livrable généré, proposer au minimum :

1. **Validation** — "Valide ce plan avec le client avant la prochaine session"
2. **Prochaine étape concrète** — action immédiate pour le porteur
3. **Prochaine session** — sujet ou objectif de la session suivante
4. **Adaptation suggérée** — si un élément mérite d'être ajusté à la niche

## Principes pédagogiques

**Système avant contenu.** On ne produit pas avant d'avoir une architecture.

**Chaque bloc débloque le suivant.** Structure → Autorité → Performance.

**Le client comprend le pourquoi.** Chaque livrable s'accompagne d'une explication stratégique.

**Résultats mesurables à chaque étape.** Un livrable tangible par bloc — pas de flou.

**L'itération est dans le système.** Le programme installe une boucle d'amélioration continue.
